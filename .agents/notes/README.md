# notes/ — 决策与依据记录

- 职责：记录「为什么这么定」—— 决策（面对岔路口选了 A 不不选 B）与依据（勘察、评估、审查等支撑决策的输入）。两类同目录、共用状态行规则。
- 每篇第 3 行是状态行；被取代的跟指针行，已归档 / 已否决的跟一句话理由。规则见 [AGENTS.md](AGENTS.md)。
- 命名：决策类 `YYYY-MM-DD-<主题>`，依据类可省日期 —— 依据是「一段时期内的调查」而不是「某天的选择」。
- **不建索引文件、不逐篇列清单**：按主题或日期翻目录树，或从根 [AGENTS.md](../../AGENTS.md) 的文档地图与正文指针进入。
- 文档间的分工：本目录答「当时为什么」；活的设计决策在 [../../docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md)，形态方案在 [../../docs/SHAPE.md](../../docs/SHAPE.md)。决策落地后的现状只写在活文档里，本目录不追改事实。
- 变更影响路由：新增或反转一条决策 → 同步根 [AGENTS.md](../../AGENTS.md) 的待办与活跃坑、以及受影响的活文档；不写「有哪些记录 / 怎么分类」，那是 [AGENTS.md](AGENTS.md) 的职责。
