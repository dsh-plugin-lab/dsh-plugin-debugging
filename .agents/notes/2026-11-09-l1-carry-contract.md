# 决策：给「层」写携带契约，并用一条判据逼着它

**日期**：2026-11-09 ｜ 状态：生效

## 问题

三层输出（L1 判定 / L2 事实 / L3 动作）从 2026-10-13 就冻在 SHAPE §3.1，但**「每层不许携什么」从未写过**。
后果在 8 个工具的模型可见文本里长成 ~29 处「同一事实说两遍」，而**三条现存红线各自差一格、全部漏掉**：

| 红线 | 它实际比的对象 | 差在哪 |
|---|---|---|
| B16 | `verdict:` + L2 行，**跨两份 fixture** | 跨 fixture，不是**同一次输出内部** |
| B18b | `why === verdict`（严格相等） | 只抓整句相等；「尾部同句」漏 |
| B20b | `sharedSubstrings(描述, 渲染文本, 40)` | 比的是**描述 ↔ 渲染**，不是 L1 ↔ L2/L3 |

触发点是一次真机会话：`dsh_sign_cookie` 把凭证写进文件之后，成功文本里 authority、落点路径、到期时刻**各出现两次**，`cookie name:` 还能由文件名推出来。

## 决策

### 一、层携带契约（SHAPE §3.0，规则本身住在那里，此处不重述）

一句话：**L1 只写判定与判定所需的量；定位符的居所是 L2；L3 只说「为什么这一步」。**

### 二、三类缺陷，修法不同（**这是本条最要紧的分法**）

| 类 | 判据 | 修法 |
|---|---|---|
| **B 类**「L1 复述 L2 字段」 | J1 / J3 抓得到 | 删 L1 那一半 |
| **C 类**「同一事实两处维护」（命名分歧 / 值可推导） | 抓不到 | 统一命名，或删掉可推导的那一处 |
| **D 类**「发布派生值」（basename / 计数 / 布尔与路径的等价） | **永远抓不到**（值形态不同） | 不印 |

**D 类必须单列**：只写「L1 别抄 L2」的话，`cookie name` ↔ 文件名、`dsh: 1` ↔ 列表条数、`markerWritten` ↔ `marker:` 路径会原样留下来。

### 三、判据 B34（J1 / J2 / J3），且**没有开关**

- J1：L1 里出现 `k=v`，且该 key 在 L2 也是 key / label。
- J2：L1 与 L2、L1 与 **L3 的 `<why>` 正文**之间 ≥40 字符逐字片段（定位符先擦掉 —— 那是 J3 的活）。
- J3：每个定位符在 **L1 ∪ L2 里恰好一次**（逐字相等、不比前缀包含、嵌套只留最长）。

**J3 的扫描面到 L2 为止**：`nextStep.args` 只**引用** L2 的定位符，而 B17 保证它必须先在别处出现过 —— 把 L3 算进去，「L2 留着」与「L2 删掉」两边都红、没有第三种可能。这条边界由**一条否证用例**钉着。

### 四、落地顺序：**判据 → 逐个工具改 → 规范**

先跑报告模式出清单、审命中时只许改判据；判据定稿后接红线、一次一个工具改到全绿；最后写这份规范。
理由：规范先写没人验，8 个工具会各按自己理解重写一遍，而**没有任何东西能告诉你写对了没有**。反过来做，判据先红、红的地方就是可执行的目标清单。

## 替代方案

- **只写规范、不写判据**（最初的想法）：8 个工具各按自己的理解重写，改完无从验收；下一批工具会照旧长回来 —— 这正是 2026-10-13 那条「同一句不许印两遍」的命运（写进了 SHAPE，然后 26 天里没人守，同类缺陷又长出 29 处）。
- **一条 40 字符 substring 判据包打全场**：抓不到 `k=v` 枚举（`oldFiberTouched=true` 只有 20 字符）—— `dsh_hot_reload` 的判定句**整句**是字段枚举，而旧判据对它完全瞎。所以拆成三条，各自窄而准。
- **J3 带白名单放行「主语型 authority」**：白名单条目不需要证明，只需要有人写一行注释；下一批要加工具的人面对红判据，最快的出路就是往白名单里加自己 —— 判据退化成登记处，且只增不减。**宁可要一条没有例外表的规则**，代价是 L1 不带定位符（而 L2 紧邻，主语不丢）。
- **让 `render` 层自动去重**：渲染期删内容会静默改语义，且与「L1 是 `data.verdict` 逐字」这条冻结契约冲突。判据是唯一干净的位置。
- **把 `data.verdict` 换成结构化投影 `table.verdict(data)`**：兜底路径（`ensureToolResult` 合成的 `internal` 失败）**没有专属 RenderTable**，换掉它那条路径就印不出判定行。§3.1 已因同一理由否决过一次。

## 影响

- **代价**：L1 变短、**信息量下降**（模型不再在判定句里看到 authority / 路径）。这是有意的取舍：它们在 L2 同一 block 里，一行之隔。
- **代价**：B34 只认逐字，D 类与「同义改写」**永远抓不到**（已写进 SHAPE 的 B34 已知限度）。它能挡回归，挡不住第一次写歪 —— 所以规范那一节仍然必要。
- **收益**：8 个工具的模型可见文本从「13 条已确认重复 + ~16 条判据抓不到的」降到 0 条已确认；并且**下一批工具在写的时候就会红**。
- **连带**：`hot_reload` 与 `check_auth` 的判定构造器**签名收窄**（只吃 decision，不收 L2 字段）—— 这是防重复最有效的一招，比判据更早生效，但无法机械验证，所以写进规范当首选写法。
