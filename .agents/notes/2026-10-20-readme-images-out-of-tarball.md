# 门面图不进 npm 包，README 一律用相对路径

**日期**：2026-10-20 ｜ **状态**：生效（**main 上已生效，npm 页面待下次发版更新**）

## 1. 起因：4 MB 动画横幅让市场的每轮构建慢在一个包上

市场每小时从 npm 抓四个插件包，只为读包里的 `locale/` 与图标。实测那一轮：

| 包 | `dist.unpackedSize`（0.7.0） | 单次下载 |
|---|---|---|
| `dsh-zhihu-search` | 263,096 B（257 KB） | 1–2 秒 |
| `dsh-ds-balance` | 530,509 B（518 KB） | 1–2 秒 |
| `dsh-workbuddy-bridge` | 502,196 B（490 KB） | 1–2 秒 |
| **`dsh-plugin-debugging`** | **5,304,492 B（5.18 MB）** | **16 秒（占整轮下载 91%）** |

`files` 里写着 `"assets"`，**整目录进包**。`assets/` 共 4,094.6 KB，其中：

| 文件 | 字节 | 引用位置 |
|---|---|---|
| `banner.gif` | 4,125,387 | **只有** `README.md:8` / `README_zh.md:8`（门面横幅，GIF89a 动画，113 帧 480×206） |
| `invoke-skill.png` | 32,471 | **只有** `README.md:51` / `README_zh.md:51`（一张截图） |
| `launcher.js` / `.d.ts` / `.vbs` / `show-window.vbs` / `stop-window.ps1` | 共 35,032 | `src/lib/restart.ts`、`src/tools/dsh_restart.ts`、`test/assets.test.ts`、`test/launcher.test.ts` —— **代码在运行期按包内路径找它们** |

整包 **78.4%** 的体积是给 README 看的两张图，而 README 的显示不需要它们出现在包里。

## 2. 结论一：这两张图**不进包**（0.7.1 起已生效）

`files` 保留 `"assets"`（运行期资产照旧自动随包），**追加两条排除**：

```json
"!assets/banner.gif",
"!assets/invoke-skill.png",
```

实测（`npm pack --dry-run`，同一棵树）：

| | 文件数 | unpacked | tarball |
|---|---|---|---|
| 改前 | 89 | 5,300,676 B（5.06 MB） | 4,498,980 B（4.29 MB） |
| 改后 | 87 | 1,143,176 B（1.09 MB） | 399,821 B（0.38 MB） |
| 差 | −2 | **−4,157,500 B（−78.4%）** | **−4,099,159 B（−91.1%）** |

发布态复核（0.7.1）：`dist.unpackedSize = 1,146,992 B`、`dist.fileCount = 90`，
下载真实 tarball 后 `package/assets/` 只剩上面那 5 个运行期文件。

## 3. 结论二：README 一律用**相对路径**（本节更正过一版，理由在此）

第一版实现把两张图改成了绝对 URL（`raw.githubusercontent.com/.../main/...`），理由是
「npm 会不会把相对路径改写到仓库 raw，编写时无法核实」。**那个前提后来被证伪**：维护者在 npm
页面上实地确认，相对路径会解析到仓库的 raw 文件、图正常显示。于是四个仓统一为**相对路径**，
绝对 URL 反而被回退掉。

为什么相对路径才对：

- **不硬编码 owner/repo/分支**。绝对 URL 把这些写进散文，仓改名或转移就静默破图；相对路径跟着仓走。
- **旧版本页面不会跟着 `main` 漂**。绝对 URL 指向 `main`，等于让历史版本的页面显示今天的图。
- **少一处维护面**：门面换图时不必同时动 URL 形状。

绝对 URL 只在「图确实在别的仓」时才该用 —— 本仓没有这种图。

## 4. 红线 B31（`test/redlines.test.ts`）

把上面两条结论一起钉住，缺一条就是另一种坏法：

1. 两份门面都用**相对路径**引用这两张图，且没有对应的绝对 raw 形态；
2. 文件**在仓里存在**（相对路径写错或文件被删时没人会收到报错，图静默不显示）；
3. 它们**没被 `files` 覆盖**（只改 README 不改 `files` 等于白改，体积一分没省）；
4. 反向：**运行期资产必须仍在包里**（防止「顺手把 assets 全排掉」，那会让代码在运行期找不到文件）。

两条否证都实测会红：把一张图改回绝对 URL → 红；删掉 `!assets/` 取反条目 → 图被算成随包 → 红。

## 5. 生效时点（重要）

- **0.7.1 已发布**：包里已经没有那两张图 —— 体积收益已生效。
- **README 的相对路径写法在 `main` 上，尚未发版**：npm 页面渲染的是**已发布版本的 README**，
  所以页面上的 URL 形状要等下一次发版才更新。这不影响显示（0.7.1 页面上的绝对 URL 同样能显示），
  但**别以为 `main` 上的改动已经在 npm 上生效**。
- 下次发版不需要额外动作：`engines.dsh` 与三族声明都没动，改动只有 README 与一处测试。

## 6. 不动的两件事，以及为什么

- **4 MB 动画 GIF 不换成 WebP**。实测两个候选：动画 WebP（`libwebp_anim -q:v 70`）**2,192,996 B**
  （只减 47%，动画还在）；静态 WebP（首帧）**41,774 B**（减 99%，但动画没了）。而动画是 2026-09
  刻意换的（`decc052`「门面横幅由 PNG 换成动图 GIF」）。前者收益不够，后者是回退作者的视觉选择
  —— 属于独立的门面决策，不在「图不该进包」这件事里。
- **`files` 不收窄成白名单**（只列 5 个运行期资产）。那样新增运行期资产会**静默不进包**，而
  `test/assets.test.ts` 从磁盘读、照样绿，只有真机才炸。「整目录 + 两条排除」方向相反：
  新增运行期资产自动进包，新增门面图最多让体积长回去（B31 会红）。
