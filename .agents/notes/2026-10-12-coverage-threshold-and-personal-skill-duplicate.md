# 覆盖率起步档 + 撤掉本机那份同名技能

状态：生效

**类型**：决策（D14 部分**待用** —— 决定已定、执行体未落）。装两条同属「外围配置」的决策：
一条管**测量**，一条管**去重**。

## 一、覆盖率起步取 wbb 档，不取官方「按文件 100%」

**背景**：官方门禁是 **`pnpm run test:coverage`：门禁级运行，对 `packages/*/*/src` 按文件 100% 覆盖**
（`[CK]\docs\testing.md:10`、`[CK]\docs\testing.zh.md:10`，2026-10-12 现读）。
**关键限定是 `packages/*/*/src`：门禁对象是宿主自己的源码树**，不是对外契约，
更不是「第三方插件仓该照抄的数字」。同段还给了理由：*未覆盖的行往往是门禁正确标记出的死代码
（应删除），而非需要补写的测试；行覆盖率是必要条件，但永远不是充分条件* ——
**它是宿主用来抓死代码的**，假定那棵树已被大量测试覆盖；搬到刚起步的插件仓上，
只会换来一堆为凑数字而写的断言。

工作区里另一份检出是唯一配了门禁的仓：`provider: 'v8'`、
`include: ['src/**/*.{ts,tsx}']`、`thresholds: { lines: 70, statements: 70, functions: 60, branches: 60 }`
（那份检出的 `vitest.config.ts:78-83`，2026-10-12 现读；别仓行号，只在该仓成立）。

**决定：起步取 wbb 那一档**（lines / statements **70**，functions / branches **60**）。

**被否的方案**：**照官方按文件 100%** —— 门禁对象不同，它不是「更严所以更好」，
而是**为另一个问题设计的**；**先不设，等测试够多** —— 把「什么时候算够」交给感觉；
**一次设到 100% 再往下调** —— 门禁一开始就是红的等于没有门禁。

**代价与重开条件（执行体未落）**：**当前 `vitest.config.ts` 里没有任何 `coverage` 配置**
（2026-10-12 现读）—— 所以本条是**决定已定、执行体未落**，覆盖率此刻**不测量**。
**触发条件（任一成立就落）**：给本仓加第一个覆盖率门禁时按此档设；
或首次发现**覆盖率盲区**（某段该测的逻辑一直没断言，且它已经出过一次错）。
**落时连带两件事**：① `@vitest/coverage-v8` **不在 devDependencies**、`node_modules` 里也没有
（2026-10-12 现读）——要同时加它，而 npm 12 会拦 postinstall，装带安装脚本的依赖前先明确
`allowScripts`（本仓 `AGENTS.md`「活跃坑」第 10 条）；② 别漏 `exclude` 里的 `lib/**`，
否则**构建产物**被计入，数字会随一次 build 变动而**源码一行没改**。
**重开**：测试体量接近那份检出、或稳定高于档位时再评估抬档。

## 二、撤掉本机个人目录里那份同名技能

**背景**：本机有一条**个人级**技能与本仓随包分发的那份**字节相同** —— 本仓
`skills/dsh-plugin-debugging/SKILL.md` 与 `~\.agents\skills\dsh-plugin-debugging\SKILL.md`，
SHA256 实测均为 `9DE75AA711486C373079DB3D43E0AD431665750BA519BC5C885171FB8A14FE25`
（2026-10-12 对两个文件各现算一次；与 recon-A「既成事实 F1」记的参考件同一哈希）。
个人级那份落在 user-agents 根、**rank 500**；本插件 runtime 注册恒为 **250**，升序小者胜
——插件上线后**压过**它（rank 方向与分层见[同目录那份](2026-10-12-runtime-skill-registration-at-rank-250.md)）。

**决定：撤掉本机那份个人级副本**，让这份知识只有一个来源。

**被否的方案**：**两份都留、靠 rank 决定谁生效** —— 技术上会覆盖，但留下**两份同源知识的漂移面**：
本仓那份随版本演进、个人目录那份不会，一旦不同步就出现「插件新版 / 个人目录旧版」，
而谁生效取决于挂载位置；更糟的是被 shadow **完全静默**（没有 API 列出被遮蔽者），
读到旧版的人收不到任何信号。**把个人级那份改成指针** —— 多一层间接且仍是副本，不如撤掉。

**代价与重开条件（顺序约束是硬的）**：**只有在本插件技能于隔离实例上被证明真的赢
（真机阶梯 **S2** 通过）之后，才撤那份个人级副本。** 理由：S2 之前，「插件那份能不能挂上、
250 是否真压过 500」**都还没验证过**；先撤再验，而插件那条链又坏了（路径解析错、
frontmatter 解析失败、被更近的层 shadow），就会出现一个**两份都不生效的窗口** ——
排障知识在最需要它的时刻整体消失，且**不报错**。**先证明新的活着，再拆旧的。**
S2 做法（recon-A 一·2、`docs/ARCHITECTURE.md` 第 8 节）：隔离实例放三份同名技能
（项目级 / 用户级 / 本插件 runtime 注册），各写**可区分的 description**，读 catalog 的
`provider` / `source` 判谁赢；预期**赢 400/500、让位 100/200**。
**代价**：S2 通过前本机同时有两份同名技能，这段时间要清楚改的是**本仓那份**。
**重开**：不需要；唯一前置就是 S2。（若将来技能改为不随包分发，本决策随之作废。）
