# test/ — 测试约定

- 职责：本仓的自动化判据。红线 = 不可被破坏的断言，随能力一起长出来；其余是冒烟与映射。
- 红线的**覆盖面**以红线文件里 `describe('B…')` 的闭集为准 —— 不在别处手抄编号清单。用例数每次改都会漂，要个数就去跑 `npm run test` 看那一行。
- 两条纪律：不依赖真机（`$DSH_HOME` 用临时目录现造）、不 mock 类（外部 IO 只从注入点进，文件系统用真的）。
- 子树：`tools/`（工具半边与共享契约的覆盖）· `skills/`（技能注册半边）· `integration/`（本机红线，不进 CI）。
- 变更影响路由：改实现 → 同步对应子目录的覆盖映射；新增或删除红线 → 同步 [../docs/SHAPE.md](../docs/SHAPE.md) 的红线清单与根 [AGENTS.md](../AGENTS.md) 待办；必跑 `npm test`。
- 判据的**已知限度**（哪条断言依赖了实现细节、改了实现会怎样）集中写在 [redlines.test.ts](redlines.test.ts) 文末那一节 —— **新增判据时同批在那张表里加一行**（不写 = 下一个人以为它没有边界）。工具测试里的**扫描类**判据也一样记在那里，别各写一份。
- 使用约束与工作偏好 → 见 [AGENTS.md](AGENTS.md)。
